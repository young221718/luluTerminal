# luluTerminal 현행 동작 계약

기준: 2026-10-23, 앱 생성 SSH 키와 종료 자원 해제가 반영된 `1bfaca4`의 구현.
이 문서는 현재 제품 요구의 정본이다. 기존 요구와 승인·검증 기록은 [정리 전 원문](history/SPEC-before-organization-2026-10-23.md)에 그대로 보존했다. 과거의 다섯 도넛 배치, 테라코타 기본색, 이 Mac의 맨 위 고정은 후속 사용자 결정으로 대체됐다.

목표는 macOS에서 약 10대의 Linux 서버 자원과 계정별 SSH/tmux 작업을 함께 관리하는 것이다. 표시 이름은 luluTerminal, 내부 bundle·실행파일·저장 경로 식별자는 InfraTerminal을 유지한다. 2026-10-23 사용자 결정으로 Ansible 개발은 취소했다. 앱의 범위는 현재 터미널·서버 연결·자원 모니터링에 집중한다. 현재 코드에는 비활성 메뉴가 남아 있지만 실행 기능은 없으며 [취소된 설계안](ANSIBLE_DESIGN.md)은 이력으로만 보존한다.

## 서버·탭·상태

| ID | 현재 계약 |
| --- | --- |
| WS-01 | 서버는 UUID, local/ssh 종류, 표시 별칭, 호스트 또는 SSH 별칭, 포트, 계정 목록, 모니터링 계정·사용 여부를 가진다. 편집 문구는 **서버 별칭**, **SSH IP(SSH 저장명)**이다. kind가 없는 기존 v1 JSON은 ssh, 인증 방식이 없는 계정은 system으로 읽는다. |
| WS-02 | 왼쪽 행을 위·아래로 드래그해 이 Mac을 포함한 서버 순서를 저장한다. 이동은 서버·계정·탭 UUID, 선택과 연결을 바꾸지 않는다. 무효 이동은 무시하고 저장 실패는 이전 순서·파일을 보존한다. |
| WS-03 | 서버별 마지막 선택 탭, 탭 순서와 닫힌 탭 기록을 복원한다. 탭 제목은 계정과 작업 이름을 표시한다. 기존 탭이 사용하는 계정 이름은 조용히 변경하지 않으며 새 계정으로 추가한다. |
| WS-04 | workspace-v1.json은 Application Support에 원자적으로 저장한다. 손상 파일을 기본값으로 덮어쓰지 않는다. 오류와 복구 경로를 표시하고 저장을 차단한다. 실제 서버 프로필·개인 키·비밀번호는 저장소에 포함하지 않는다. |
| LOCAL-01 | 예약 UUID의 이 Mac을 한 번만 제공한다. 처음 추가할 때 맨 위에 놓되 저장된 순서는 유지한다. 일반 편집·제거는 막는다. 실제로 비어 있는 첫 실행에서만 로컬 Mac·기본 셸을 선택하고 기존 원격 선택·기록은 유지한다. |
| LOCAL-02 | 선택한 로컬 탭은 로그인 셸을 홈에서 실행한다. SSH/tmux 경로에 진입하지 않는다. 탭 전환은 surface를 재사용하고, 닫거나 앱을 종료한 뒤 다시 열면 새 셸을 시작한다. 로컬 작업 지속은 보장하지 않는다. |
| DEMO-01 | 명시적 데모는 가상 서버 10대와 실제 로컬 Mac을 구분한다. 가상 서버 SSH 실행과 실사용 상태 파일 쓰기는 하지 않는다. |

## 터미널·인증

| ID | 현재 계약 |
| --- | --- |
| TERM-01 | Ghostty 전체 엔진을 AppKit NSView에 임베딩한다. PTY·렌더링·입력은 실제 엔진을 사용하고 엔진 누락을 분명히 표시한다. HTML 또는 가짜 출력으로 대체하지 않는다. |
| TERM-02 | SSH 탭마다 서버+계정+탭 UUID의 고유 원격 tmux 세션을 사용한다. 제목·서버 표시 이름·순서 변경은 세션 identity를 바꾸지 않는다. 입력 검증과 셸 인용으로 인자·옵션 주입을 막는다. |
| TERM-03 | 새 탭 또는 사용자가 명시적으로 새 세션 만들기를 선택한 경우에만 세션을 생성한다. 일반 재접속은 기존 세션에만 붙고 없으면 사용자에게 명시적 생성을 요청한다. 다른 클라이언트를 강제 detach하지 않는다. 비대화형 확인 실패는 명시적 대화형 인증 경로를 제공한다. |
| TERM-04 | 탭 닫기·해제·앱 종료는 로컬 연결을 닫으며 원격 tmux 작업을 종료하지 않는다. 원격 세션 종료 기능은 없다. 서버 재부팅·원격 프로세스 종료 후 복원은 보장하지 않는다. |
| TERM-05 | 자연 종료 콜백이 반환된 뒤 종료 surface와 스크롤 기록을 해제한다. generation 검사로 같은 탭 UUID에 재연결한 새 surface와 다른 탭을 보존한다. 종료 안내와 인증 실패를 구분한다. |
| SSH-01 | system 인증은 시스템 OpenSSH·기존 설정을 사용하며 기존 개인 키를 복사하지 않는다. 호스트키 확인을 무력화하지 않는다. 자동 모니터링은 비대화형이다. |
| SSH-02 | 기존 password 인증은 호스트·포트·계정과 해석된 SSH 대상에 묶인 Keychain 참조만 JSON에 둔다. 원문은 Keychain에만 저장한다. 빈 입력과 system/managedKey 전환은 기존 참조를 유지한다. 명시적 비밀번호 삭제·교체 또는 해당 계정 제거를 성공적으로 저장한 뒤에만 더 이상 참조하지 않는 기존 항목을 지운다. 취소·저장 실패·대상 변경은 기존 자격 증명을 보존한다. |
| SSH-03 | 비밀번호 자동 인증은 확인된 호스트키·일반 password·직접 연결에 한정한다. 경유·OTP·HostKeyAlias는 수동/기존 키 경로를 사용한다. 자동 인증 실패는 명시적 재시도나 자격 증명 수정까지 수집을 멈춘다. |
| SSH-04 | 배경 Keychain 조회는 권한 창을 금지한다. 사용자 명시 연결의 사전 확인과 실제 터미널에만 허용한다. 독립 도우미 신원은 같은 Core 소스·툴체인에서 UI·빌드 경로 변경에 유지된다. 최초 접근·잠긴 키체인·도우미 변경의 OS 승인은 별도다. |
| SSH-05 | 비밀번호 칸은 실제 보안 입력 필드다. 한글 입력기 또는 한글 문자를 감지하면 영어 입력 안내만 표시한다. 입력기·문자를 자동 변경하거나 저장을 차단하지 않는다. |
| KEY-01 | managedKey는 계정 전용 Ed25519 키를 별도 네이티브 설정 터미널에서 생성한다. 최초 서버 인증과 선택한 키 암호는 사용자가 직접 입력한다. 암호 없는 키를 암호화됐다고 표시하지 않는다. 개인 키는 Application Support/InfraTerminal/SSHKeys 아래 사용자 전용 디렉터리·파일 권한으로 보관한다. |
| KEY-02 | 공개 키만 authorized_keys에 추가한다. 기존 바이트·키·원격 tmux 작업을 보존하고 심볼릭 링크와 예상 밖 파일 종류를 거부한다. 실패한 시도와 기존 키를 자동 삭제하지 않는다. |
| KEY-03 | 검증하고 적용에서 지정 키만 사용하는 독립 SSH true 확인, 최신 대상 재확인, 상태 저장이 모두 성공해야 전환한다. SSH 설정·multiplexing·다른 IdentityFile로 성공을 대신하지 않는다. 취소·중복 설정·대상 변경·저장 실패는 기존 인증을 유지한다. 휴면 비밀번호 참조는 명시적 삭제 전까지 보존한다. |
| KEY-04 | managedKey 경로는 UseKeychain=no와 askpass 금지를 적용한다. 암호 있는 키는 로그인 세션 ssh-agent에 등록해 재사용하며 agent 초기화 후 명시적 잠금 해제를 제공한다. 터미널·검증·모니터링에 같은 검증된 대상·agent를 전달한다. 정상 터미널 종료는 모니터링 인증 실패가 아니다. |

## 자원·화면

| ID | 현재 계약 |
| --- | --- |
| MON-01 | 사용자 터미널에 명령을 타이핑하지 않고 별도 SSH로 /proc/stat, /proc/meminfo, /proc/net/dev, df -PTk, 선택적 nvidia-smi를 수집한다. 선택 서버 기본 2초(2·5·10초), 나머지 10초 목표. 서버별 중복 수집을 막고 원격 동시 실행은 최대 3개다. 응답이 느리면 실제 간격은 길어진다. |
| MON-02 | CPU는 total/idle 차분, RAM은 MemTotal-MemAvailable, 네트워크는 counter와 실제 경과 시간의 차분이다. 차분 지표의 첫 표본·재부팅·counter 감소와 0분모·누락·잘못된 값은 계산 불가로 표시한다. RAM·디스크·GPU는 유효한 첫 표본부터 표시할 수 있다. 오류를 정상 0으로 바꾸지 않는다. |
| MON-03 | Linux 디스크는 pseudo 파일시스템을 제외한 마운트별 값이며 공유 용량을 합산하지 않는다. GPU는 UUID·index와 개별 사용률·VRAM, 네트워크는 인터페이스별 값을 제공한다. 기존 전체 요약 필드는 호환성을 위해 유지한다. |
| MON-04 | macOS CPU·RAM·디스크는 추가 권한 없이 로컬 API로 수집한다. RAM은 active+inactive+wired+compressed로 캐시를 포함하며 Activity Monitor와 같다고 주장하지 않는다. 상세 디스크는 보이는 로컬 마운트의 캐시 통계, 기존 요약은 홈 볼륨이다. APFS 공유 용량을 합산하지 않는다. 로컬 GPU·VRAM·네트워크는 미지원이다. |
| MON-05 | 표본 시각과 목표 주기 3배 이후 stale 상태를 표시한다. 이력은 서버당 최대 450개이면서 최근 900초로 제한한다. 재실행·긴 공백을 연결하지 않는다. 수집 프로세스의 기본 timeout은 8초, 합계 출력 상한은 1 MiB다. 취소·timeout 때 로컬 프로세스를 회수한다. |
| UI-01 | 왼쪽은 서버명과 날개 없는 부엉이다. 눈 뜸은 열린 터미널 프로세스이며 인증 성공을 단정하지 않는다. 자원은 오른쪽 기본 240pt 패널에 모은다. CPU·RAM·네트워크는 한 행이다. GPU는 최대 네 열, 바깥 틸 사용률·안쪽 연두 VRAM의 붙은 동심원과 중앙 사용률 숫자 또는 작은 막대를 제공한다. |
| UI-02 | 저장 공간은 마운트별 막대·남은 용량, 남은 비율 10% 이하 주의를 표시한다. 미지원·미수집은 —로 표시한다. 자원 상세와 기록도 우측에서 연다. |
| UI-03 | 경계의 <·> 버튼과 드래그로 양쪽 패널을 접고 펼친다. 펼친 너비는 왼쪽 160–320pt, 오른쪽 220–400pt. 마지막 너비를 저장하고 좁은 창은 터미널 최소 340pt를 우선한다. 패널 변경은 터미널 surface를 재생성하지 않는다. |
| UI-04 | 상단 앱 아이콘·브랜드·항상 보이는 설정 진입점과 ⌘,를 제공한다. 설정은 외관·글꼴·보기 및 모니터링·일반의 독립 창이다. 라이트 기본, 화이트·차콜·딥 틸 팔레트이며 기존 사용자 지정값을 보존한다. 모드별 색상 개별 저장·복원을 지원한다. |
| UI-05 | 설치된 고정폭 폰트, 10–28pt, 기본 Menlo 14pt. 외관·폰트는 별도 사용자 설정에 저장하고 기존 셸·출력을 유지하며 즉시 적용한다. 크기 변경은 탭별 확대를 설정 크기로 맞추고 색 변경은 확대 상태를 유지한다. 잘못된 저장값은 기본값으로 대체한다. |
| UI-06 | 사용량 막대·GPU 동심원·숫자는 수집 목표 간격의 90%(기본 1.8초) 동안 선형 보간한다. 보간이 표본·수집 주기를 바꾸지 않는다. 동작 줄이기 설정을 따른다. |
| UI-07 | 한글 입력 소스·Caps Lock에서도 Command-C/V/Q를 물리 키 fallback으로 처리하고 Control-C와 Shift/Option 조합을 보존한다. 실제 한국어 IME 조합 입력과 접근성 수락 검증은 별도다. |

## 검증과 후속 범위

[TESTING](TESTING.md)은 요구와 검사 위치, [VERIFICATION](VERIFICATION.md)은 실제 검사 결과·한계를 기록한다. 자동 검사, native UI 수락, 실서버 접속, release 빌드, 설치, CI, 서명·공증은 서로 대체하지 않는다.

실서버 검증은 명시적으로 지정·승인된 대상에서만 수행한다. 자동 테스트에 실사용 자격 증명을 넣지 않는다. 최초 실제 공개 키 등록, 로그인 세션 초기화 후 잠금 해제, 장시간 수집, Intel 실기기·VoiceOver·한국어 IME는 아직 별도 수락 대상이다. 앱은 ad-hoc 서명이며 Developer ID·공증·자동 업데이트는 제공하지 않는다.

Ansible 실행기·의존성 설치·플레이북 실행은 개발 취소 범위다. [이전 설계](ANSIBLE_DESIGN.md)의 구현 단계와 검사는 활성 TODO가 아니다. 기존 기능의 안정성과 사용성 개선은 구체적인 사용자 선택 후 별도로 범위를 정한다.
