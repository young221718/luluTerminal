# luluTerminal macOS 첫 버전

승인: 2026-10-19, 도넛형 v3 화면과 개발 진행 요청. 표시 브랜드 luluTerminal, 내부 식별자 InfraTerminal 유지.
목표는 약 10대의 Linux 서버 상태를 보며 계정별 터미널 작업을 다시 여는 macOS 앱이다.
추가 승인: 2026-10-19, 현재 Mac을 항상 표시하고 바로 사용할 수 있는 로컬 셸을 제공한다.
UI 변경: 2026-10-19, 도넛 중앙에 작은 숫자를 넣고 사용률 구간별 색을 연속 그라데이션으로 표시한다.

브랜딩 적용: 2026-10-19, 올루루 아이콘과 네이비·민트 색상을 적용하며 화면 배치·서버 행·계정 탭 동작은 유지한다.

외관 변경: 2026-10-21, 사용자가 라이트·다크 선택을 요청했다. 이어 1차 색 조합을 거절하고 더 정돈된 색상과 별도 색상·글꼴 설정 탭을 요청했다. 라이트는 오프화이트, 다크는 차콜, 포인트는 테라코타를 기본으로 한다. 기본값은 라이트이며 설정을 저장한다. 기존 화면 배치와 서버·탭 동작을 유지한다.

## 동작 계약
구현 변경: 2026-10-22, 기본 팔레트는 화이트·차콜과 딥 틸로 갱신하되 기존 사용자 지정 팔레트는 보존한다. 오른쪽 모니터 시안과 명시적 설정 진입점·앱 아이콘을 실제 앱에 적용한다. 최신 화면 요구가 이전 서버별 다섯 도넛 배치를 대체한다. 보기·표시 자원·수집 on/off·갱신 간격은 사용자 설정에 저장하며 기존 서버·탭 JSON을 변경하지 않는다.

1. 서버 프로필은 UUID, 연결 종류(`local`/`ssh`), 이름, 호스트 또는 SSH 별칭, 포트, 계정 목록, 모니터링 계정을 가진다. 기존 v1 JSON에 연결 종류가 없으면 `ssh`로 읽는다. 계정별 인증 방식은 기존 SSH 키·설정 또는 저장 비밀번호다. 기존 JSON에서 인증 방식이 없으면 SSH 키·설정으로 읽는다. 비밀번호는 macOS 키체인에만 보관하고 JSON에는 대상에 묶인 참조만 저장한다. SSH 연결은 시스템 OpenSSH를 사용하며 호스트키 확인을 무력화하지 않는다. 비밀번호 자동 인증은 확인된 호스트·일반 password 인증·직접 연결에 한정한다. 경유 SSH·OTP·HostKeyAlias는 수동/키 인증 경로를 사용한다. 취소·저장 실패는 기존 자격 증명을 보존하며 대상 변경 시 재입력을 요구한다. 자동 인증 실패 후에는 사용자 재시도 또는 자격 증명 수정 전까지 해당 계정 수집을 멈춘다. 배경 수집은 키체인 권한 창을 띄우지 않으며 접근 허용이 필요하면 그 이유를 표시한다. 명시적인 연결의 사전 확인과 터미널에서만 권한 창을 허용한다. UI와 분리된 도우미의 코드 신원은 같은 Core 소스·툴체인 기준으로 UI 변경과 빌드 경로 변경에도 유지한다. 새 도우미의 최초 접근은 계정별 승인이 필요하며 ‘허용’은 현재 조회만, ‘항상 허용’은 후속 자동 연결·수집에 적용된다.
2. 왼쪽 목록은 서버 이름과 날개 없는 연결 상태 부엉이만 표시한다. 눈 뜸은 해당 서버에 열린 터미널 프로세스가 있는 상태이며 SSH 인증 성공을 단정하지 않는다. 자원은 오른쪽 기본 240pt 패널에 놓는다. 양쪽 경계 버튼으로 패널을 각각 접고 펼치며 드래그로 왼쪽 160–320pt, 오른쪽 220–400pt 너비를 조절한다. 접으면 마지막 펼친 너비를 보존한다. 창이 좁으면 터미널 최소 340pt를 우선하며, 화면 구성을 바꿔도 터미널 표면은 재생성하지 않는다. CPU·메모리·네트워크는 한 행, GPU는 실제 개수대로 최대 네 열의 틈 없는 사용률 틸/VRAM 연두 동심원과 중앙 사용률 숫자를 표시한다. 저장 공간은 마운트별 막대와 남은 용량, 남은 비율 10% 이하 주의 표시를 제공한다. 미지원·미수집은 0%와 구분한다.
3. 서버를 선택하면 그 서버의 탭을 표시한다. 탭 제목에 계정과 작업 이름을 함께 표시한다. 서버별 마지막 선택 탭과 순서를 앱 재실행 후 복원한다. 왼쪽 서버 행을 드래그하면 대상 행의 위·아래에 삽입한다. 이 Mac을 포함한 서버 순서를 저장하고 재실행 후 복원한다. 이동은 서버·계정·탭 ID나 선택, 기존 연결을 변경하지 않는다. 서버 추가·편집 입력 문구는 ‘서버 별칭’, ‘SSH IP(SSH 저장명)’이다.
4. SSH 앱 탭마다 서버+계정에 종속된 고유 원격 tmux 세션을 둔다. 탭마다 별도 세션을 사용해 같은 세션을 여러 클라이언트에서 선택할 때 생기는 창 전환 간섭을 방지한다. UUID에서 만든 세션 식별자는 화면 제목 변경과 무관하다. 서버 UUID·계정 UUID·탭 UUID를 포함하며 shell 입력을 섞지 않는다.
5. SSH 새 탭을 만들 때만 원격 세션을 생성한다. 재접속은 기존 세션만 붙이며 세션이 없으면 명시적으로 알린다. 사용자가 새 세션 만들기를 선택하기 전 자동 재생성하지 않는다. 다른 클라이언트를 강제 detach하지 않는다.
6. SSH 탭 닫기는 로컬 보기와 SSH 연결만 닫는다. 원격 tmux 작업은 종료하지 않는다. 닫힌 탭을 로컬 기록에 보존해 다시 열 수 있다. 원격 세션 종료 기능은 첫 버전에 넣지 않는다. 앱 종료·네트워크 단절 후 원격 서버와 tmux가 살아 있으면 작업을 이어간다. 서버 재부팅·프로세스 종료는 복원 보장 밖이다.
7. Ghostty 전체 엔진을 AppKit NSView에 임베딩한다. 명령 실행·PTY·렌더링은 Ghostty가 맡고 UI는 SwiftUI/AppKit을 사용한다. HTML 터미널이나 가짜 출력으로 구현을 대체하지 않는다. 엔진을 구할 수 없으면 빌드/화면에 분명히 표시한다.
8. 앱 실행 중 별도 SSH 명령으로 Linux `/proc/stat`, `/proc/meminfo`, `/proc/net/dev`, `df -PTk`, 선택적 NVIDIA `nvidia-smi`를 수집한다. 사용자 터미널에 명령을 타이핑하지 않는다. SSH는 비대화형·시간 제한·호스트키 검증 유지. 선택 서버 기본 2초(2·5·10초 선택), 나머지 10초; 수집은 서버별 중첩하지 않고 동시 실행을 제한한다.
9. CPU는 두 표본의 total/idle counter 차분. RAM은 MemTotal-MemAvailable. 디스크는 마운트별로 수집하며 pseudo 파일시스템을 제외하고 공유 저장 공간을 합산하지 않는다. macOS는 보이는 로컬 볼륨의 캐시 통계만 조회한다. GPU와 VRAM은 UUID·index가 있는 개별 장치 값을 기본 표시하고, 기존 전체 요약은 상세 기록에서 유지한다. 상세에 장치·네트워크 인터페이스별 값을 제공한다. 네트워크는 monotonic counter 차분/실제 시간. 초기 표본·재부팅·counter 감소·0분모·잘못된 응답은 계산 불가로 표현한다.
10. 표본에 수집 시각을 기록한다. 수집 주기 3배 이상 지나면 마지막 값과 갱신 중단을 표시한다. 실패를 정상 0으로 바꾸지 않는다. 차트는 앱 실행 중 표본만 사용하며 재실행/긴 공백을 선으로 연결하지 않는다.
11. 서버 추가·편집, 계정 선택, 모니터링 계정 선택, 연결/해제/재접속, 닫은 탭 다시 열기, 자원 상세, 설정을 제공한다. Ansible은 예정 메뉴와 비활성 필드만 제공한다.
12. 기본 목록 맨 위에 현재 Mac을 한 번만 고정 표시하며 일반 서버 편집으로 변경하거나 제거할 수 없다. 실제로 비어 있는 첫 실행에서는 로컬 Mac과 기본 셸 탭을 선택한다. 기존 원격 서버 선택·계정·탭·닫힌 기록은 유지한다. 명시적 데모에는 가상 서버 10대와 실제 로컬 Mac을 구분해서 표시하며 가상 서버로 SSH를 실행하지 않는다. 데모는 실사용 저장 파일을 변경하지 않는다.
13. 저장은 버전 있는 JSON을 앱 Application Support에 원자적으로 기록한다. 손상 파일을 기본값으로 덮어쓰지 않고 오류와 복구 경로를 표시한다. SSH 로그인 계정 변경은 기존 탭의 계정 정체성을 조용히 바꾸면 안 된다.
14. 로컬 Mac은 예약한 서버·계정 UUID를 사용하고 현재 로그인 이름을 표시한다. 로컬 탭은 현재 로그인 셸을 홈 디렉터리에서 실행하며 SSH·tmux 명령에 진입하지 않는다. 선택한 로컬 탭은 바로 사용할 수 있도록 셸을 연다. 탭 전환은 기존 Ghostty surface를 재사용한다. 새 탭·닫기·다시 열기를 지원하지만 로컬 탭을 닫거나 앱을 종료한 뒤에는 새 셸을 시작하며 작업 지속을 보장하지 않는다.
15. 로컬 지표는 권한 추가 없이 macOS API로 CPU counter 차분, 물리 RAM, 홈 디렉터리가 속한 단일 볼륨 용량을 수집한다. RAM 사용량은 `(active + inactive + wired + compressed) × pageSize`이며 회수 가능한 캐시를 포함한다고 표시한다. Activity Monitor와 같은 사용량이라고 주장하지 않는다. APFS 공유 용량은 홈 볼륨 한 번만 읽고 여러 볼륨 값을 합산하지 않는다. 로컬 GPU·VRAM·네트워크는 미지원으로 표시하며 nil 또는 빈 배열을 유지한다. 로컬 지표와 셸은 원격 수집·SSH 실행 경로와 분리한다.

16. 항상 보이는 상단 설정 또는 ⌘,로 독립 설정 창을 열고 외관·글꼴·보기 및 모니터링·일반 탭을 제공한다. 외관에서 라이트·다크를 고르고 각 모드의 배경·글자·포인트 색을 별도 저장한다. 유효한 저장값이 없으면 라이트와 기본 팔레트를 사용한다. 현재 모드의 색상만 복원할 수 있다. 창·사이드바·시트·터미널 팔레트를 함께 바꾸고 기존 Ghostty surface·로컬 셸·SSH 연결을 다시 만들지 않는다. 새로 여는 탭도 현재 스타일을 사용한다.
17. 글꼴에서 설치된 고정폭 폰트와 10–28pt 크기를 선택하고 미리보기·기본값 복원을 제공한다. 기본값은 Menlo 14pt다. 폰트·색상 설정은 서버·탭 JSON과 별도 사용자 설정에 저장한다. 크기를 변경하면 기존 탭별 확대·축소를 설정 크기로 맞추고 색만 바꿀 때는 확대 상태를 유지한다. 유효하지 않은 저장값은 안전한 기본값을 사용한다.

## 앱 생성 SSH 키 계약 (2026-10-23)

사용자는 키체인을 사용하지 않는 SSH 키 자동 생성·서버 등록을 선택했다. 계정별 인증에 `managedKey`를 추가하며 기존 JSON은 그대로 읽는다. `managedKey` 참조는 UUID 및 입력/해석된 서버·계정 대상에 묶고 비밀을 저장하지 않는다.

별도 설정 터미널에서 native ssh-keygen과 ssh-add를 사용한다. 키 암호는 사용자가 선택하며 암호 없는 키를 암호화되어 있다고 표시하지 않는다. 최초 서버 인증 후 공개 키만 authorized_keys에 추가한다. 기존 파일 내용·기존 키·원격 tmux 작업을 유지하고 심볼릭 링크 및 예상 밖 파일 종류를 거부한다. 실패한 시도를 자동으로 삭제하지 않는다.

사용자가 검증하고 적용을 누르면 지정된 키로만 별도 SSH true를 실행한다. 다른 IdentityFile이나 공유 연결로 성공을 대신하지 않도록 설정 파일과 multiplexing을 배제한다. 대상·계정이 바뀌거나 취소·저장 실패가 발생하면 기존 인증 상태를 유지한다. 저장 비밀번호 참조는 전환과 이후 일반 저장에서도 보존하며 명시적 삭제에만 제거한다.

앱 생성 키의 모든 경로에서 UseKeychain=no 및 askpass 금지를 적용한다. 암호가 있는 키는 로그인 세션 ssh-agent에 한 번 등록해 재사용하고 agent 초기화 후 명시적 잠금 해제를 제공한다. 모니터링에서 인증이 실패하면 자동 반복을 멈춘다. 설정 시트는 독립 터미널을 사용하고 닫을 때 자신의 프로세스/표면만 해제한다. 종료 콜백이 온 일반 터미널의 표면·스크롤 기록도 콜백 반환 뒤 해제하며, 같은 탭 ID에 재연결한 새 표면은 이전 콜백의 영향을 받지 않는다. 정상 키 인증 터미널 종료만으로 모니터링 인증을 실패로 처리하지 않는다. 실제 자격 증명 입력과 최초 실서버 등록은 사용자가 설치 앱에서 수행한다.

## 검증 경계

로컬 자동 테스트, 앱 빌드·실행, 실제 SSH 서버, NVIDIA GPU, 서명/공증·배포를 별도로 보고한다.
실서버는 사용자가 테스트 대상을 지정/승인하기 전 접근하지 않는다. 원격 collector 설치와 Ansible 실행은 후속 범위다.
