# luluTerminal 현행 동작 계약

기준: 2026-10-28, 비밀번호 한 번으로 SSH 키 자동 설정, 계정 수정·삭제·서버 삭제, Keychain·저장 비밀번호 제거, 연결 복구·터미널 검색·빠른 이동, 편집창의 모니터링 갱신 격리를 포함한 현행 구현 계약.
이 문서는 현재 제품 요구의 정본이다. 기존 요구와 승인·검증 기록은 [정리 전 원문](history/SPEC-before-organization-2026-10-23.md)에 그대로 보존했다. 과거의 다섯 도넛 배치, 테라코타 기본색, 이 Mac의 맨 위 고정은 후속 사용자 결정으로 대체됐다.

목표는 macOS에서 약 10대의 Linux 서버 자원과 계정별 SSH/tmux 작업을 함께 관리하는 것이다. 표시 이름은 luluTerminal, 내부 bundle·실행파일·저장 경로 식별자는 InfraTerminal을 유지한다. 2026-10-23 사용자 결정으로 Ansible 개발은 취소했다. 앱의 범위는 현재 터미널·서버 연결·자원 모니터링에 집중한다. 비활성 Ansible 메뉴·안내는 화면에서 제거했으며 [취소된 설계안](ANSIBLE_DESIGN.md)은 이력으로만 보존한다.

## 서버·탭·상태

| ID | 현재 계약 |
| --- | --- |
| WS-01 | 서버는 UUID, local/ssh 종류, 표시 별칭, 호스트 또는 SSH 별칭, 포트, 계정 목록, 모니터링 계정·사용 여부를 가진다. 편집 문구는 **서버 별칭**, **SSH IP(SSH 저장명)**이다. kind가 없는 기존 v1 JSON은 ssh, 인증 방식이 없는 계정은 system으로 읽는다. |
| WS-02 | 왼쪽 행을 위·아래로 드래그해 이 Mac을 포함한 서버 순서를 저장한다. macOS 27에서는 기본 재정렬의 행 들어 올리기·삽입 빈칸·주변 행 이동을 사용하며 작업이 끝났을 때만 모델에 반영한다. 이전 macOS는 행 미리보기와 놓은 뒤 순서 전환을 사용한다. 이동은 서버·계정·탭 UUID, 선택과 연결을 바꾸지 않는다. 취소·무효 이동은 저장하지 않고 저장 실패는 이전 순서·파일을 보존한다. 단일 행 이동만 지원한다. |
| WS-03 | 서버별 마지막 선택 탭, 탭 순서와 닫힌 탭 기록을 복원한다. 탭 제목은 계정과 작업 이름을 표시한다. 계정 이름 변경은 영향 확인 뒤 새 계정 UUID로 저장하며 이전 계정의 열린 탭·닫힌 탭 기록만 앱에서 제거한다. 이전 원격 세션을 다른 사용자에게 연결하지 않는다. |
| WS-04 | workspace-v1.json은 Application Support에 원자적으로 저장한다. 손상 파일을 기본값으로 덮어쓰지 않는다. 오류와 복구 경로를 표시하고 저장을 차단한다. 실제 서버 프로필·개인 키·비밀번호는 저장소에 포함하지 않는다. |
| WS-05 | 서버 편집에서 계정 이름 수정·삭제를 제공한다. 저장 시 변경·삭제 계정과 영향을 받는 열린 탭·닫힌 탭 기록을 확인한다. 이름 변경은 관리 키 참조를 해제하고 pendingKey로 전환하며 새 계정의 앱 전용 키를 설정한다. 삭제된 모니터링 계정은 남은 첫 계정으로, 이름이 바뀐 모니터링 계정은 새 UUID로 연결한다. 마지막 계정 삭제는 막고 서버 삭제를 안내한다. |
| WS-06 | SSH 서버 메뉴에서 이름·탭 수를 확인한 뒤 앱의 서버 등록과 해당 탭 기록을 삭제한다. 원격 계정·파일·tmux 세션과 로컬 SSH 키 파일은 삭제하지 않는다. 저장 성공 뒤 로컬 연결·수집을 정리하고 선택을 유효한 남은 항목으로 복구한다. 취소·저장 실패는 기존 상태·연결을 보존하며, 삭제·수정 전 비동기 결과는 무효화한다. |
| LOCAL-01 | 예약 UUID의 이 Mac을 한 번만 제공한다. 처음 추가할 때 맨 위에 놓되 저장된 순서는 유지한다. 일반 편집·제거는 막는다. 실제로 비어 있는 첫 실행에서만 로컬 Mac·기본 셸을 선택하고 기존 원격 선택·기록은 유지한다. |
| LOCAL-02 | 선택한 로컬 탭은 로그인 셸을 홈에서 실행한다. SSH/tmux 경로에 진입하지 않는다. 탭 전환은 surface를 재사용하고, 닫거나 앱을 종료한 뒤 다시 열면 새 셸을 시작한다. 로컬 작업 지속은 보장하지 않는다. |
| DEMO-01 | 명시적 데모는 가상 서버 10대와 실제 로컬 Mac을 구분한다. 가상 서버 SSH 실행과 실사용 상태 파일 쓰기는 하지 않는다. |

## 터미널·인증

| ID | 현재 계약 |
| --- | --- |
| TERM-01 | Ghostty 전체 엔진을 AppKit NSView에 임베딩한다. PTY·렌더링·입력은 실제 엔진을 사용하고 엔진 누락을 분명히 표시한다. HTML 또는 가짜 출력으로 대체하지 않는다. |
| TERM-02 | SSH 탭마다 서버+계정+탭 UUID의 고유 원격 tmux 세션을 사용한다. 제목·서버 표시 이름·순서 변경은 세션 identity를 바꾸지 않는다. 입력 검증과 셸 인용으로 인자·옵션 주입을 막는다. |
| TERM-03 | 새 탭 또는 사용자가 명시적으로 새 세션 만들기를 선택한 경우에만 세션을 생성한다. 일반 재접속은 기존 세션에만 붙고 없으면 사용자에게 명시적 생성을 요청한다. 다른 클라이언트를 강제 detach하지 않는다. 기존 system 계정의 비대화형 확인 실패는 명시적 대화형 인증 경로를 제공한다. pendingKey 계정은 키 설정 완료를 안내하고 대화형 기존 키 인증으로 우회하지 않는다. |
| TERM-04 | 탭 닫기·해제·앱 종료는 로컬 연결을 닫으며 원격 tmux 작업을 종료하지 않는다. 원격 세션 종료 기능은 없다. 서버 재부팅·원격 프로세스 종료 후 복원은 보장하지 않는다. |
| TERM-05 | 자연 종료 콜백이 반환된 뒤 종료 surface와 스크롤 기록을 해제한다. generation 검사로 같은 탭 UUID에 재연결한 새 surface와 다른 탭을 보존한다. 종료 안내와 인증 실패를 구분한다. |
| TERM-06 | ⌘F는 현재 실행 중인 터미널의 Ghostty 검색을 연다. Return·⌘G는 다음 결과, ⇧⌘G는 이전 결과, Escape는 닫기다. 같은 surface의 출력·스크롤 기록을 검색하며 새 SSH·surface를 만들지 않는다. 탭 전환·연결 종료 때 검색을 닫고 UUID·generation이 지난 콜백을 무시한다. |
| SSH-01 | system 인증은 시스템 OpenSSH·기존 설정을 사용하며 기존 개인 키를 복사하지 않는다. 호스트키 확인을 무력화하지 않는다. 접속 가능한 인증 방식은 system/managedKey이며, pendingKey는 새 키 설정 전 접속을 차단하는 저장 상태다. |
| SSH-02 | 기존 저장 비밀번호 보관 계약을 대체한다. 이전 authMethod=password는 system으로 읽고 credential 참조 메타데이터는 구조와 무관하게 무시한다. 서버·계정·탭 UUID, 선택·순서·원격 세션 identity는 유지한다. 새 JSON에는 password 방식과 credential 참조를 쓰지 않는다. 과거 키체인 항목 삭제 여부는 별도 작업의 확인 범위다. |
| SSH-03 | 최초 공개 키 등록은 앱에서 서버 비밀번호를 한 번 받아 자동 수행한다. 비밀번호는 일시적 메모리와 분리된 로컬 인증 PTY 채널에서만 사용한다. 사전 확인·모니터링·자동 복구는 비대화형 키 인증만 사용한다. 수동 비밀번호 로그인만으로 배경 인증이 충족되지는 않는다. 자동 인증 실패는 명시적 재시도까지 수집을 멈춘다. |
| SSH-04 | 기존 Keychain 조회·도우미 계약을 대체한다. 앱의 비밀번호 저장소·Keychain API·인증 도우미·askpass 경로를 제거한다. 앱이 실행하는 모든 SSH에 UseKeychain=no, AddKeysToAgent=no, SSH_ASKPASS_REQUIRE=never를 적용한다. 배포 앱에서 제거 여부를 검사한다. |
| SSH-05 | 서버·계정 편집에는 비밀번호 저장·삭제 UI가 없다. 새 계정의 인증 행은 선택지 없이 ‘새 SSH 키 자동 설정’을 표시하며, 저장 상태는 pendingKey다. 기존 system·managedKey 계정의 인증 설정과 누락 값·legacy password의 system 변환은 유지한다. 이름 변경 계정도 pendingKey로 저장한다. 새 서버·추가 계정·이름 변경 계정을 성공적으로 저장하면 편집창을 닫은 뒤 저장된 최종 계정 ID로 SSH 키 설정 화면을 자동으로 연다. 여러 대상은 성공 후 다음 계정으로 이어지고 취소하면 나머지 안내를 닫되 저장한 계정과 pendingKey 상태는 유지한다. pendingKey는 앱 재실행 후에도 터미널·사전 확인·모니터링·자동 복구를 실행하지 않으며 기존 키로 대체 접속하지 않는다. 서버 메뉴의 ‘SSH 키 설정’에서 다시 시작할 수 있다. 단순 서버 설정 변경·기존 계정·데모·편집 취소·저장 실패에서는 자동 설정을 시작하지 않는다. 보안 입력칸과 자동 설정 버튼으로 최초 등록을 수행하고 입력값을 즉시 비운다. 기존 system 계정의 인증 오류에도 자동 설정 진입을 제공한다. 생성·등록·검증 진행 상태와 실패를 표시하며 별도 수동 검증 버튼을 요구하지 않는다. 기존 암호화 키 잠금 해제는 네이티브 터미널을 유지한다. |
| SSH-06 | SSH 종료 코드 255를 네트워크·인증·호스트키·원인 불명으로 구분한다. 네트워크 실패를 키 잠금 해제로 안내하지 않는다. 자동 복구는 인증·호스트키·원인 불명에서 재시도를 막고 명시적 확인·수동 연결을 안내한다. 호스트키 검증을 우회하지 않는다. |
| KEY-01 | 자동 설정은 계정 전용의 암호 없는 Ed25519 키를 새 UUID 경로에 생성한다. 개인 키는 Application Support/InfraTerminal/SSHKeys 아래 디렉터리 0700·파일 0600으로 보관하며 암호화되지 않음을 UI에 표시한다. 기존 참조의 requiresAgent 누락은 true, 새 자동 생성 키는 false로 저장하여 로그인 세션 agent 없이 키 파일로 인증한다. |
| KEY-02 | 공개 키만 authorized_keys에 추가한다. 기존 바이트·키·원격 tmux 작업을 보존하고 심볼릭 링크와 예상 밖 파일 종류를 거부한다. 실패한 시도와 기존 키를 자동 삭제하지 않는다. |
| KEY-03 | 자동 설정은 키 생성 → 비밀번호로 공개 키 등록 → 지정 키만 사용하는 독립 SSH true 확인 → 최신 대상 재확인 → 원자적 상태 저장 순서다. 모든 단계가 성공해야 pendingKey에서 managedKey로 전환한다. 기존 계정의 명시적 재설정도 검증과 저장 성공 뒤에만 전환한다. SSH 설정·multiplexing·다른 IdentityFile로 성공을 대신하지 않는다. 취소·중복 설정·대상 변경·저장 실패는 직전 인증 상태를 유지하고 진행 중 작업을 취소한다. 신규 계정은 pendingKey로 남으며 기존 키를 사용하지 않는다. 이미 생성·등록된 키는 임의로 삭제하지 않는다. |
| KEY-04 | 모든 SSH의 공통 Keychain·askpass 금지 정책을 따른다. 새 자동 키는 IdentityAgent=none으로 지정 키 파일만 사용하며 별도 잠금 해제가 필요 없다. 기존 암호화 키는 로그인 세션 ssh-agent를 사용하고 로그아웃·재시작·agent 초기화 후 잠금 해제가 필요할 수 있다. 터미널·검증·모니터링의 대상과 키 정책이 같아야 한다. 정상 터미널 종료는 모니터링 인증 실패가 아니다. |
| KEY-05 | 비밀번호 등록 SSH는 password만 1회 허용하고 호스트키를 엄격히 확인한다. 원격 stdout/stderr와 로컬 /dev/tty를 분리하여 원격 배너에 암호를 보내지 않는다. NUL·CR·LF 없는 1~1023 UTF-8 바이트를 허용한다. argv·환경변수·파일·진단 출력에 비밀번호를 넣지 않는다. 원문 인증 출력을 반환하지 않고 정적 분류 오류를 사용한다. 출력 상한·전체 제한 시간·취소 시 소유 프로세스 그룹 종료와 직접 자식 회수를 보장한다. 모르는/변경된 호스트키, keyboard-interactive/MFA는 자동으로 수락하지 않는다. |

## 연결 복구

| ID | 현재 계약 |
| --- | --- |
| REC-01 | 설정의 일반 → 연결 복구에서 절전·네트워크 복귀 후 재접속을 선택한다. 기본값은 꺼짐이며 workspace JSON과 별도 사용자 설정에 저장한다. 활성화하면 절전·네트워크 중단 및 복귀·경로 변경 이벤트를 모으고 중복 복귀를 합친다. 초기 정상 네트워크 알림만으로 재접속하지 않는다. |
| REC-02 | 복구 대상은 SSH 키·기존 설정 또는 managedKey로 열어 둔 기존 탭이다. 닫힌 탭·로컬·데모·pendingKey 계정은 제외한다. 기존 tmux 세션 확인에 성공한 경우만 재접속하며 없는 세션은 만들지 않는다. 비대화형 인증·확인된 호스트키만 사용하고 인증·키 잠금 해제 창을 띄우지 않는다. |
| REC-03 | 자동 복구 전 SSH 설정을 확인하며 ProxyJump·ProxyCommand·HostKeyAlias가 필요한 연결은 수동 재시도로 남긴다. 복구를 위해 SSH 경로·포워딩 설정을 제거하거나 다른 대상으로 바꾸지 않는다. 실패 때 무한 반복하지 않으며 수동 해제·탭 닫기·프로필 변경·설정 끄기 뒤 오래된 결과를 연결에 적용하지 않는다. 원격 tmux 작업은 종료하지 않는다. |

## 자원·화면

## 검증과 후속 범위

[TESTING](TESTING.md)은 요구와 검사 위치, [VERIFICATION](VERIFICATION.md)은 실제 검사 결과·한계를 기록한다. 자동 검사, native UI 수락, 실서버 접속, release 빌드, 설치, CI, 서명·공증은 서로 대체하지 않는다.

실서버 검증은 명시적으로 지정·승인된 대상에서만 수행한다. 자동 테스트에 실사용 자격 증명을 넣지 않는다. 최초 실제 공개 키 등록, 로그인 세션 초기화 후 잠금 해제, 실제 절전·네트워크 변경 후 복구, 검색·빠른 이동의 native 포커스·단축키, 장시간 수집, Intel 실기기·VoiceOver·한국어 IME는 별도 수락 대상이다. 앱은 ad-hoc 서명이며 Developer ID·공증·자동 업데이트는 제공하지 않는다.

Ansible 실행기·의존성 설치·플레이북 실행은 개발 취소 범위다. [이전 설계](ANSIBLE_DESIGN.md)의 구현 단계와 검사는 활성 TODO가 아니다. 기존 기능의 안정성과 사용성 개선은 구체적인 사용자 선택 후 별도로 범위를 정한다.
