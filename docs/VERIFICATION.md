# 검증 안내

## 로컬 검사와 빌드

macOS 14 이상, Swift 6.2 이상과 Command Line Tools가 필요하다. arm64 macOS 27.0.1·Swift 6.4 환경에서 개발했다. 처음 의존성을 받을 때는 네트워크가 필요하다.

```bash
bash scripts/test.sh
bash -n scripts/build-app.sh scripts/make-icon.sh scripts/test.sh
bash scripts/build-app.sh
codesign --verify --deep --strict 'dist/Infra Terminal.app'
open 'dist/Infra Terminal.app'
```

자동 검사는 계정별 세션 격리, SSH 인자 인용과 입력 검증, 생성/재접속 분리, 상태 저장, 로컬 라우팅, 지표 계산, 수집 스케줄, 프로세스 제한과 터미널 컨테이너 소유권을 다룬다. 실제 SSH 서버나 사용자의 저장 데이터에 접속하지 않는 fixture 검사와 로컬 프로세스 검사를 사용한다.

아이콘은 `Resources/AppIcon.png`에서 macOS `sips`·`iconutil`로 재생성한다. 패키지의 고정된 바이너리 체크섬과 의존성 잠금 파일을 유지한다. 임시 iconset, 빌드 캐시와 앱 번들은 Git에 포함하지 않는다.

## 실제 화면 확인

- 설정 → 외관에서 라이트·다크를 왕복하고 창·사이드바·독립 설정 창·터미널이 함께 바뀌는지 확인한다. 본문·보조 글자·선택 행·ANSI 출력이 각 배경에서 읽혀야 한다.
- 설정 버튼과 ⌘,가 동일한 독립 설정 창을 여는지 확인한다. 외관·글꼴·보기 및 모니터링·일반 탭의 내용과 현재 모드 색상·폰트의 개별 기본값 복원을 확인한다.
- 로컬 셸에서 PID와 표식 문자열을 출력하고 색상·폰트·크기를 바꾼 뒤 PID·이전 출력·입력이 유지되는지 확인한다. 새 탭과 숨겨진 탭에도 현재 스타일을 적용해야 한다. 기존 탭을 확대한 뒤 설정에서 크기를 바꾸면 새 크기로 맞춰야 하며, 색만 바꿀 때는 확대 상태를 유지해야 한다.
- 라이트·다크에 서로 다른 사용자 색을 지정해 각각 유지되는지 확인하고, 앱을 다시 열어 외관·색·폰트·크기 선택이 복원되는지 확인한다. 실사용 앱을 확인할 때에는 설치된 앱 하나만 사용하고 기존 설정을 기록한 뒤 확인 후 복원한다. 별도 미리보기 앱을 실행하거나 실사용 서버·탭 데이터를 바꾸지 않는다.
- 기본 로컬 Mac 한 개와 로컬 셸 자동 시작, 우측 CPU·메모리·네트워크 행과 GPU 미지원·저장 공간 표시 확인.
- 서버/계정 탭 전환, 창 크기 변경, 복사/붙여넣기와 키보드 입력 확인.
- 승인된 Linux 서버에서만 새 전용 tmux 탭 생성, 연결 해제 및 기존 세션 재접속 확인.
- 모니터링 실패와 실제 0을 구분하고 수집 시각·오류를 확인.
- 앱 종료는 원격 tmux 세션을 종료하지 않지만 서버 재부팅·tmux 종료·로컬 셸 지속을 보장하지 않는다.

소스 검사, 앱 빌드, 실제 서버 확인, CI, 서명·공증과 배포는 서로 다른 검증 단계다. 한국어 IME 전체 조합, VoiceOver, 장시간 10대 수집, 네트워크 장애와 Intel Mac 실기기 검증은 아직 완료되지 않았다.

## 오른쪽 자원 패널 회귀 확인

- 양쪽 경계의 접기/펼치기 버튼을 각각 눌러 반대 패널에 영향을 주지 않고 마지막 너비로 복원되는지 확인한다. 경계 드래그로 확대·축소·접기·다시 펼치기를 확인한다.
- 작은 창에서 양쪽 패널이 큰 너비로 저장된 상태에서도 드래그가 반대 방향으로 움직이거나 튀지 않는지 확인한다. 최소 터미널 너비와 실행 중인 셸 PID·출력·입력이 유지되어야 한다.

- 상단 앱 아이콘과 설정 버튼은 터미널 집중 모드에서도 표시한다.
- 보기 모드·패널 표시·GPU 동심원/막대·자원 항목·수집 on/off·2/5/10초 주기를 바꾸고 재실행 복원을 확인한다. 수집을 꺼도 터미널 프로세스와 탭 UUID는 유지한다.
- GPU 0/1/4/8개, VRAM 일부 누락, 유효한 0%, 여러 마운트와 공백 경로, 부족한 남은 용량을 확인한다. 링은 바깥 틸/안쪽 연두가 맞닿고 중앙 숫자는 사용률만 표시한다.
- 모니터링 꺼짐·오류·갱신 지연은 실제 0과 구분한다. 부엉이는 수집 상태가 아닌 터미널 프로세스 상태를 표시한다. SSH 인증 완료를 독립적으로 검출하지 않는다.
- `--demo`는 서버 저장 파일과 실사용 외관·모니터링 설정에 쓰지 않는다. 데모 설정은 별도 사용자 설정 도메인으로 저장한다.

- 사이트는 HTML 참조·JS 상호작용·작은 텍스트 대비 검사와 실제 브라우저의 서버/탭 전환, 테마/폰트, 버튼·키보드·포인터 패널 조절을 확인했다. 320·375·390·650·850·851·1024·1440px 화면에서 페이지 가로 넘침이 없었다. VoiceOver 전체 수락 검증은 포함하지 않았다.

## 2026-10-22 저장 비밀번호 인증 확인 결과

- 최종 소스의 전체 96개 검사·13개 suite 통과. 기존 키 인증 호환, 대상 변경 시 재사용 거부, 키체인/JSON 저장 실패 롤백, 인증 실패 시 자동 재시도 중단, 같은 계정의 동시 연결과 취소 회귀 검사를 포함한다.
- release 빌드와 엄격한 ad-hoc 서명 검사 통과. 21개 오픈소스 원문 고지 검사를 유지했다.
- 실제 macOS 키체인에 무작위 임시 비밀번호를 저장·조회·삭제했다. 같은 Core 인증 코드를 쓰는 UI 없는 검증 실행파일과 로컬 임시 SSH 서버로 사전 확인·터미널·모니터링의 비밀번호 인증을 확인했다. 인증 시도는 3회, 모니터링 스크립트 stdin은 1,020바이트이며 미확인 호스트에는 비밀번호를 보내지 않았다. 검증용 키체인 항목은 정리했다. 이 검사는 실서버 계정이나 설치 앱의 최초 키체인 승인 동작을 대신하지 않는다.
- 설치 번들의 askpass wrapper는 잘못된 호출을 종료 코드 1과 빈 출력으로 거부했다. 설치된 앱에서 인증 선택·보안 입력 필드·키체인 안내를 표시하고 취소를 확인했다. 별도 미리보기 앱을 실행하지 않았다.
- 기존 앱 백업 후 `/Applications/luluTerminal.app`을 직접 갱신했다. 빌드와 설치 번들의 55개 파일이 일치하며 설치 및 UI 취소 전후 서버·탭 상태 파일 해시가 동일했다.
- 실서버 비밀번호 인증은 사용자가 앱에 자격 증명을 직접 저장한 뒤 확인해야 한다. OTP·경유 SSH·HostKeyAlias의 저장 비밀번호 자동 인증, Developer ID 서명·공증, CI와 Intel 실기기 검증은 포함하지 않는다.
